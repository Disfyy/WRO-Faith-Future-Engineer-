## 3. Этап 1: Подготовка шасси

### 3.1. Разборка лишнего
HSP 94182 идёт с приёмником, ESC и кузовом. Всё это нужно снять:

1. Снять кузов (клипсы по углам)
2. Отключить и снять стоковый ESC (электронный регулятор скорости)
3. Отключить стоковый приёмник
4. Оставить: шасси + подвеска + мотор + серво-крепление + колёса

> [!WARNING]
> **НЕ СНИМАЙТЕ** рулевые тяги и рычаги подвески. Их настройка влияет на геометрию руля. Если снимите — обратно собрать без инструкции сложно.

### 3.2. Замена пиньона (если нужно)
Если стоковый пиньон имеет другой шаг (M0.48 или M0.5), его нужно заменить на M0.6:

1. Ослабить стопорный винт пиньона (шестигранник 1.5мм)
2. Сдёрнуть пиньон с вала мотора (может потребоваться съёмник или нагрев феном)
3. Надеть новый пиньон 16T M0.6 Ø2.3мм
4. Затянуть стопорный винт **на лыске** вала
5. Проверить зазор с основной шестернёй: должен быть ~0.1мм (лист бумаги между зубьями, провернуть, вынуть)

> [!TIP]
> Если шестерни гудят — зазор слишком тугой. Если щёлкают — слишком свободный. Идеально — свободное вращение без люфта.

### 3.3. Установка серво
1. Установить JX PDI-6221MG в штатное серво-крепление HSP
2. Закрепить 4 винтами (идут в комплекте с серво)
3. Установить качалку серво, чтобы при нейтральном положении (90°) колёса смотрели прямо
4. Подключить рулевую тягу к качалке

> [!IMPORTANT]
> **КРИТИЧНО:** Качалка серво устанавливается **ДО подачи питания на серво**. Если поставить качалку криво — робот будет ехать боком. Проверка: при отключенном питании колёса должны свободно поворачиваться рукой.

### 3.4. Измерение диаметра колёс

Это критично для одометрии:

1. Снять одно колесо
2. Измерить **внешний диаметр** штангенциркулем под нагрузкой (слегка прижать)
3. Записать значение: D = _____ мм
4. Вычислить: `TICKS_PER_CM = 4096 / (π × D_мм) × 10`
5. Записать в код `eps323.cpp` строку `#define TICKS_PER_CM`

**Пример:** D = 75мм → C = 235.6мм → 4096/235.6 = 17.38 тиков/мм = **174 тиков/см**

✅ **Проверка этапа 1:**
- [ ] Шасси чистое: нет ESC, приёмника, кузова
- [ ] Пиньон на месте, зубья не гудят
- [ ] Серво установлено, колёса прямо при 90°
- [ ] Диаметр колёс записан

## 4. Этап 2: Силовая цепь

> [!CAUTION]
> **ПОЛЯРНОСТЬ!** Перепутать + и − на LiPo = мгновенное горение электроники. Каждый провод проверять мультиметром ПЕРЕД подключением.

### 4.1. Схема питания

```
LiPo 7.4V ──T-plug──▶ Переходник T→XT60 ──▶ XT60 разъём
                                                  │
                      ┌───────────────────────────┤
                      │                           │
                KCD3 #1 (ГЛАВНЫЙ)            KCD3 #2 (ЛОГИКА)
                      │                           │
              BTS7960 (VCC, GND)            LM2596 #1 → 5V
              Мотор через драйвер           (ESP32, серво, датчики 5V)
                                                  │
                                            LM2596 #2 → 3.3V
                                            (OpenMV, датчики 3.3V)
```

### 4.2. Настройка LM2596

> [!WARNING]
> Настроить выходное напряжение **ДО** подключения электроники! Подключить вход к батарее, крутить подстроечник мультиметром на выходе.

**LM2596 #1 (5V):**
1. Подключить вход к батарее через KCD3 #2
2. Включить
3. Мультиметром на выходе МЕДЛенно крутить подстроечник до **5.00V ± 0.05V**
4. Нагрузить резистором 100 Ом (проверить что держит под нагрузкой)
5. Отключить

**LM2596 #2 (3.3V):**
1. Аналогично настроить на **3.30V ± 0.05V**
2. Нагрузить, проверить

> [!TIP]
> Пометьте каждый LM2596 маркером: «5V» и «3.3V». Через месяц забудете какой где.

### 4.3. Пайка силовых проводов

1. Отрезать 14 AWG провод: 2 красных по 15 см, 2 чёрных по 15 см
2. Зачистить концы на 5мм
3. Припаять XT60 разъём к проводам от батареи
4. Припаять провода к KCD3 переключателям:
   - KCD3 #1: разрыв + линии к BTS7960
   - KCD3 #2: разрыв + линии к LM2596 входам
5. Все соединения закрыть **термоусадкой**

### 4.4. Фильтрация питания

> [!IMPORTANT]
> Мотор 380 создаёт МОЩНЫЕ помехи на шине питания. Без фильтрации I2C будет зависать, UART — терять пакеты.

1. Припаять **конденсатор 0.1 мкФ** (керамический, 104) прямо на клеммы мотора (между + и −)
2. Припаять ещё один 0.1 мкФ между каждой клеммой мотора и корпусом (3 конденсатора суммарно на мотор)
3. Припаять 0.1 мкФ на вход питания BTS7960 (VCC-GND)
4. Припаять 0.1 мкФ на выход каждого LM2596 (VOUT-GND)

**Схема конденсаторов мотора:**
```
        0.1µF
  (+)────┤├────(−)      ← между клеммами
         │
  (+)────┤├────(корпус)  ← клемма + к корпусу
  (−)────┤├────(корпус)  ← клемма − к корпусу
```

✅ **Проверка этапа 2:**
- [ ] LM2596 #1 выдаёт 5.00V ± 0.05V
- [ ] LM2596 #2 выдаёт 3.30V ± 0.05V
- [ ] KCD3 #1 включает/отключает силовую линию
- [ ] KCD3 #2 включает/отключает логическую линию
- [ ] Конденсаторы на моторе (3 шт), на BTS7960, на LM2596
- [ ] Все пайки закрыты термоусадкой
- [ ] Мультиметр: нет КЗ между + и −

## 5. Этап 3: Мотор и драйвер BTS7960

### 5.1. Подключение BTS7960

| BTS7960 пин | Подключение | Провод |
|-------------|-------------|--------|
| **B+** (VCC) | 7.4V от KCD3 #1 (+) | 14AWG красный |
| **B-** (GND) | 7.4V от KCD3 #1 (−) | 14AWG чёрный |
| **M+** | Мотор клемма + | 14AWG |
| **M-** | Мотор клемма − | 14AWG |
| **VCC** (логика) | 5V от LM2596 #1 | Dupont |
| **GND** (логика) | GND общий | Dupont |
| **R_EN** | ESP32 GPIO19 | Dupont |
| **L_EN** | ESP32 GPIO23 | Dupont |
| **RPWM** | ESP32 GPIO5 | Dupont |
| **LPWM** | ESP32 GPIO14 | Dupont |

> [!WARNING]
> **R_EN и L_EN** должны быть HIGH для работы мотора. В коде это делается в `setup()`. Если мотор не крутится — первым делом проверьте эти пины мультиметром.

### 5.2. Проверка направления

1. Подключить питание
2. В Serial Monitor отправить команду, чтобы мотор крутился вперёд
3. Если колёса крутятся **назад** — поменять M+ и M− местами на BTS7960
4. Зафиксировать провода

✅ **Проверка этапа 3:**
- [ ] Мотор крутится в правильную сторону
- [ ] BTS7960 не греется при холостом ходе
- [ ] Конденсатор на клеммах мотора установлен

## 6. Этап 4: Рулевой серво

### 6.1. Подключение

| Серво провод | Подключение |
|--------------|-------------|
| **Красный** (+) | 5V от LM2596 #1 |
| **Коричневый** (−) | GND общий |
| **Оранжевый** (сигнал) | ESP32 GPIO18 |

> [!WARNING]
> **НЕ питайте серво от 3.3V пина ESP32!** PDI-6221MG потребляет до 2.5A при нагрузке — это сожжёт ESP32 мгновенно. Только от LM2596 5V.

### 6.2. Калибровка центра

1. Загрузить на ESP32 тестовый скетч:
```cpp
#include <ESP32Servo.h>
Servo s;
void setup() { s.attach(18, 500, 2500); }
void loop() { s.write(90); delay(100); }
```
2. Подать питание
3. Колёса должны встать прямо
4. Если не прямо — снять качалку серво, переставить на 1-2 шлица, повторить
5. Записать значение SERVO_CENTER: _____° (обычно 88-92)

> [!TIP]
> Точная калибровка: если при `write(90)` колёса чуть влево — SERVO_CENTER = 92. Тонкая подстройка в `eps323.cpp`.

✅ **Проверка этапа 4:**
- [ ] Серво центрировано: колёса прямо при SERVO_CENTER
- [ ] Серво отрабатывает полный диапазон 45°-135° без заеданий
- [ ] Серво работает от 5V LM2596, НЕ от ESP32

## 7. Этап 5: ESP32 — мозг

### 7.1. Установка

1. Закрепить ESP32 DevKitC V4 на макетной плате через гребёнку
2. Макетную плату закрепить на шасси через двусторонний скотч 3M
3. USB-разъём ESP32 должен быть доступен снаружи (для прошивки и отладки)

> [!IMPORTANT]
> **Расположение:** ESP32 подальше от мотора и BTS7960! EMI от мотора 380 может вызвать сбои I2C и UART. Минимум 5 см расстояния.

### 7.2. Общая GND

Самая частая причина проблем — **нет общей земли**.

Соединить GND всех компонентов между собой:
- ESP32 GND
- BTS7960 GND (логичеcкий)
- LM2596 #1 GND
- LM2596 #2 GND
- OpenMV GND
- Все датчики GND

> [!CAUTION]
> **«Звездообразная» земля:** Все GND провода сходятся в ОДНУ точку на макетной плате. НЕ делайте цепочку GND→GND→GND — это создаёт петли и наводки.

### 7.3. Питание ESP32

| ESP32 пин | Подключение |
|-----------|-------------|
| **5V** (пин VIN или 5V) | 5V от LM2596 #1 |
| **GND** | Общая GND |

> [!WARNING]
> Можно питать ESP32 через VIN (5V) или через USB. **НЕ оба одновременно!** При отладке по USB — отключать VIN.

✅ **Проверка этапа 5:**
- [ ] ESP32 загорается при подаче 5V
- [ ] Serial Monitor работает (отправить «Hello»)
- [ ] GND общий между ESP32, BTS7960, LM2596, датчиками (прозвонка мультиметром)

## 8. Этап 6: I2C шина (TCA9548A + датчики)

### 8.1. Зачем мультиплексор

У нас 2 × AS5600 (оба с адресом 0x36) и 2 × VL53L1X (оба с адресом 0x29). Без TCA9548A они конфликтуют.

### 8.2. Подключение TCA9548A

| TCA9548A пин | Подключение |
|--------------|-------------|
| **VIN** | 3.3V от LM2596 #2 |
| **GND** | Общая GND |
| **SDA** | ESP32 GPIO21 |
| **SCL** | ESP32 GPIO22 |
| **A0** | GND (адрес 0x70) |
| **A1** | GND |
| **A2** | GND |
| **RST** | Не подключен (внутренний pull-up) |

### 8.3. I2C Pull-up резисторы

> [!IMPORTANT]
> **КРИТИЧНО!** ESP32 имеет слабые внутренние pull-up (~45 кОм). При частоте 400 кГц и длинных проводах I2C будет сбоить. НУЖНЫ внешние pull-up.

Подключить резисторы **4.7 кОм**:
- Один резистор: **SDA → 3.3V**
- Один резистор: **SCL → 3.3V**

Место установки: **на шине между ESP32 и TCA9548A** (самый короткий путь).

> [!TIP]
> Pull-up ставятся ТОЛЬКО на главную шину (ESP32 ↔ TCA). На каждом канале TCA pull-up НЕ НУЖНЫ — TCA буферизует сигнал.

### 8.4. Уровни напряжения

| Компонент | Логика |
|-----------|--------|
| ESP32 | 3.3V |
| TCA9548A | Работает с 3.3V и 5V |
| AS5600 | 3.3V или 5V |
| ICM-20948 | 3.3V |
| VL53L1X | 3.3V |

Все датчики питаем от **3.3V**. Преобразователь уровней 3.3↔5V **не нужен для I2C** если всё на 3.3V. Он нужен только если какой-то датчик 5V-only.

### 8.5. Карта каналов TCA9548A

| TCA канал | Датчик | I2C адрес | Длина провода |
|:---------:|--------|:---------:|:-------------:|
| CH0 | ICM-20948 (IMU) | 0x69 | ≤ 10 см |
| CH1 | AS5600 (левый) | 0x36 | 15-25 см |
| CH2 | AS5600 (правый) | 0x36 | 15-25 см |
| CH3 | VL53L1X (фронт) | 0x29 | 15-20 см |
| CH4 | VL53L1X (бок) | 0x29 | 15-20 см |
| CH5-7 | Свободны | — | — |

> [!WARNING]
> **Длина проводов I2C** — критичный фактор. При 400 кГц максимум ~30 см. Если провод длиннее — снизить частоту до 100 кГц или использовать экранированный кабель.

### 8.6. Проверка I2C — запуск сканера

1. Загрузить на ESP32 файл `scanerI2C.cpp`
2. Открыть Serial Monitor (115200 бод)
3. Ожидаемый результат:
```
Канал [0]: 0x69 ICM-20948 (IMU, AD0=VCC)
Канал [1]: 0x36 AS5600 (энкодер)
Канал [2]: 0x36 AS5600 (энкодер)
Канал [3]: пусто  ← будет 0x29 когда подключим VL53L1X
Канал [4]: пусто  ← будет 0x29 когда подключим VL53L1X
СТАТУС: ВСЕ ДАТЧИКИ В НОРМЕ
```

✅ **Проверка этапа 6:**
- [ ] TCA9548A отвечает по адресу 0x70
- [ ] Pull-up 4.7 кОм на SDA и SCL главной шины

## 9. Этап 7: Энкодеры AS5600

### 9.1. Принцип работы

AS5600 — магнитный энкодер. Магнит (Ø6мм) крепится на оси, AS5600 считывает угол через Hall-эффект. Даёт 4096 позиций за оборот (12 бит).

### 9.2. Установка магнитов

> [!CAUTION]
> Это самый сложный механический этап. Магнит должен быть **точно над центром чипа** AS5600 на расстоянии **0.5-3 мм**.

**Левый энкодер (CH1):**
1. Определить ось, вращающуюся пропорционально левому колесу (обычно полуось или карданный вал)
2. Приклеить магнит Ø6мм на торец оси (двусторонний скотч или суперклей)
3. Закрепить плату AS5600 напротив магнита на расстоянии 1-2 мм
4. Вращать колесо рукой → значение AS5600 должно плавно меняться 0→4095→0

**Правый энкодер (CH2):**
1. Аналогично для правого колеса

> [!TIP]
> **Проверка магнита:** В Serial Monitor выводить `readEncoder(1)`. При вращении колеса рукой значение должно плавно меняться. Если скачет хаотично — магнит слишком далеко или не отцентрирован.

### 9.3. Подключение

| AS5600 пин | Подключение |
|------------|-------------|
| VCC | 3.3V |
| GND | GND |
| SDA | TCA CH1 (или CH2) SDA |
| SCL | TCA CH1 (или CH2) SCL |
| DIR | Не подключен (или GND) |

✅ **Проверка этапа 7:**
- [ ] Оба энкодера видны сканером (CH1: 0x36, CH2: 0x36)
- [ ] При вращении левого колеса значение CH1 плавно меняется
- [ ] При вращении правого колеса значение CH2 плавно меняется
- [ ] Магниты надёжно закреплены (не отвалятся при вибрации)

## 10. Этап 8: IMU (ICM-20948)

### 10.1. Подключение GY-ICM20948V2

| IMU пин | Подключение |
|---------|-------------|
| VCC | 3.3V |
| GND | GND |
| SDA | TCA CH0 SDA |
| SCL | TCA CH0 SCL |
| AD0 | 3.3V (адрес 0x69) или GND (адрес 0x68) |

> [!IMPORTANT]
> Убедитесь что AD0 подтянут к **3.3V** (адрес 0x69). Код ожидает именно этот адрес. Если AD0 = GND, адрес будет 0x68 и `icm.begin_I2C()` вернёт ошибку.

### 10.2. Установка

1. Закрепить IMU **горизонтально** на шасси (ось Z смотрит вверх)
2. Ось X направить **вперёд** по направлению движения
3. Закрепить на виброизоляционной прокладке (кусок поролона + двусторонний скотч)

> [!WARNING]
> **Вибрация** от мотора 380 — главный враг IMU. Без виброизоляции гироскоп будет дрейфовать в 3-5 раз быстрее. Используйте мягкую прокладку!

### 10.3. Калибровка гироскопа

Калибровка автоматическая в `calibrateGyro()` при старте:
- Робот должен **стоять неподвижно** 3 секунды
- Код усредняет 300 значений Z-оси гироскопа
- Результат сохраняется в `gyroZbias`

✅ **Проверка этапа 8:**
- [ ] IMU виден на CH0 (адрес 0x69)
- [ ] `calibrateGyro()` выдаёт bias < 0.05 (Serial Monitor)
- [ ] При повороте робота рукой yawAngle меняется плавно
- [ ] IMU на виброизоляции, горизонтально, ось X вперёд

## 11. Этап 9: Камера OpenMV H7 Plus

### 11.1. Подключение UART

| OpenMV пин | ESP32 пин | Описание |
|------------|-----------|----------|
| P4 (TX) | GPIO16 (RX) | OpenMV передаёт → ESP32 принимает |
| P5 (RX) | GPIO17 (TX) | ESP32 передаёт → OpenMV принимает |
| GND | GND | Общая земля |
| VIN | 5V от LM2596 #1 | Питание камеры |

> [!CAUTION]
> **TX ↔ RX перекрёстное подключение!** TX камеры идёт в RX контроллера и наоборот. Если подключить TX к TX — данных не будет, но ничего не сгорит.

> [!WARNING]
> **Уровни напряжений:** OpenMV H7 Plus работает на 3.3V логике. ESP32 тоже 3.3V. Преобразователь уровней для UART **НЕ НУЖЕН**. Но если вы случайно запитаете OpenMV через 5V пин на GPIO — может сгореть.

### 11.2. Установка камеры

1. Закрепить камеру на передней части шасси, **смотрящей вперёд**
2. Высота камеры: **8-12 см** от пола (оптимально для обнаружения столбов и линий)
3. Наклон: **10-15° вниз** от горизонта (чтобы видеть и далёкие объекты и пол)
4. Зафиксировать жёстко (никакой вибрации!) — скотч 3M + кабельная стяжка

> [!TIP]
> Угол наклона камеры КРИТИЧЕН. Слишком горизонтально — не видит линии на полу. Слишком вниз — не видит далёкие столбы. Компромисс: ~12° вниз.

### 11.3. Прошивка OpenMV

1. Подключить OpenMV к компьютеру через USB
2. Открыть OpenMV IDE
3. Открыть `src/openmv/openmv_main.py`
4. **НЕ запускать напрямую!** Сначала откалибровать пороги (см. Этап 15)
5. После калибровки: Tools → Save Script to OpenMV Cam (as `main.py`)

✅ **Проверка этапа 9:**
- [ ] OpenMV IDE видит камеру
- [ ] В Serial Monitor ESP32 появляются данные UART (даже мусорные до калибровки)
- [ ] Камера жёстко закреплена, не вибрирует
- [ ] Высота 8-12 см, наклон ~12° вниз

## 13. Этап 11: Кнопки E-STOP и MODE

### 13.1. E-STOP (GPIO32)

```
3.3V ──[10кОм]──┬── GPIO32 (INPUT_PULLUP)
                 │
              [КНОПКА]
                 │
                GND
```

Или проще: подключить кнопку между GPIO32 и GND. `INPUT_PULLUP` в коде подтянет пин к 3.3V. Нажатие = LOW.

### 13.2. MODE Switch (GPIO4)

```
3.3V ──[10кОм]──┬── GPIO4 (INPUT_PULLUP)
                 │
             [ТУМБЛЕР KCD3]
                 │
                GND
```

- **Тумблер включен (LOW):** Obstacle Challenge
- **Тумблер выключен (HIGH):** Open Challenge

> [!TIP]
> Используйте KCD3 с фиксацией (ON-OFF), а не кнопку без фиксации. Режим выбирается перед гонкой и не меняется.

✅ **Проверка этапа 11:**

- [ ] Кнопка E-STOP доступна снаружи робота (не закрыта другими деталями)

## 15. Этап 13: Сборка проводки

### 15.1. Организация проводов

> [!IMPORTANT]
> Неаккуратная проводка — причина 80% проблем на соревнованиях. Потратьте время сейчас, сэкономите нервы на WRO.

1. **Разделите силовые и сигнальные провода** — они НЕ должны идти параллельно

4. **Кабельные стяжки** каждые 5-7 см зафиксировать к шасси

Мультиметром проверить:
- [ ] Нет КЗ между 7.4V и GND

- [ ] Нет КЗ между 3.3V и GND
- [ ] GND все компоненты соединены (0 Ом между GND пинами)
- [ ] SDA и SCL не замкнуты друг на друга

✅ **Проверка этапа 13:**
- [ ] Силовые и сигнальные провода разведены
- [ ] Все провода зафиксированы стяжками

## 17. Этап 15: Калибровка и первый запуск

### 17.1. Калибровка цветовых порогов (OpenMV)

> [!CAUTION]
> **Это самый важный этап!** Неправильные пороги = робот не видит столбы = не объезжает = дисквалификация.

**Порядок:**

1. Подключить OpenMV к компьютеру
2. Открыть `openmv_main.py` в OpenMV IDE
3. Поставить робота на трек (или перед объектами нужных цветов)
4. Tools → Machine Vision → Threshold Editor
5. Для каждого цвета:
   a. Направить камеру на объект
   b. Двигать ползунки L, A, B пока в маске не останется ТОЛЬКО нужный цвет
   c. Записать значения в соответствующую строку кода

| Цвет | Переменная | Что калибровать |
|------|------------|-----------------|
| 🟠 Оранжевая линия | `THRESHOLD_ORANGE` | Оранжевая полоска на мате |
| 🔵 Синяя линия | `THRESHOLD_BLUE` | Синяя полоска на мате |
| 🔴 Красный столб | `THRESHOLD_RED` | Красный цилиндр на треке |
| 🟢 Зелёный столб | `THRESHOLD_GREEN` | Зелёный цилиндр на треке |
| 🩷 Малиновый блок | `THRESHOLD_MAGENTA` | Малиновый парковочный блок |
| ⬛ Чёрная стена | `THRESHOLD_WALL` | Чёрный борт трека |

> [!TIP]
> Калибровать при **том же освещении**, что будет на соревнованиях! Дневной свет и LED-лампы дают разные цвета. Если не знаете — калибруйте и включите `set_auto_exposure(False, exposure_us=10000)`.

### 17.2. Калибровка фокусной константы

1. Поставить красный столб на **ровно 20 см** от камеры
2. Запустить скрипт, посмотреть raw `blob.w()` в IDE
3. `FOCAL_CONST = 20 × blob.w()`
4. Записать в код

### 17.3. Калибровка одометрии

1. Пометить стартовую позицию колеса
2. Прокатить робота **ровно 100 см** по прямой линейкой
3. Записать delta `totalDistLeft`
4. `TICKS_PER_CM = delta / 100`

### 17.4. Первый запуск (на полу, без трека)

1. Поставить робота на пол (не на трек!)
2. Включить оба KCD3
3. LED должен мигать (STATE_INIT)
4. Нажать E-STOP → отпустить → LED горит → робот поехал
5. Нажать E-STOP → робот остановился
6. Отпустить E-STOP → робот продолжил

### 17.5. Первый запуск на треке

1. Переключить MODE на OPEN
2. Поставить на трек
3. Запустить
4. Робот должен проехать 3 круга и остановиться
5. Если не проехал — анализировать Serial Monitor

### 17.6. Тест Obstacle Challenge

1. Переключить MODE на OBSTACLE
2. Расставить красные и зелёные столбы
3. Запустить
4. Красные — справа, зелёные — слева
5. 3 круга → парковка

✅ **Финальная проверка:**
- [ ] Все цвета откалиброваны
- [ ] FOCAL_CONST и TICKS_PER_CM записаны
- [ ] E-STOP работает (остановка + продолжение)
- [ ] MODE Switch переключает режимы
- [ ] Open Challenge: 3 круга + парковка
- [ ] Obstacle Challenge: объезд столбов + парковка
- [ ] LED показывает состояние

## 18. Типичные проблемы и их решения

### 🔌 I2C зависает
| Симптом | Причина | Решение |
|---------|---------|---------|
| Робот зависает через 5-10 сек | I2C зависание от EMI мотора | Добавить конденсаторы на мотор (0.1 мкФ) |
| Энкодеры «пропадают» | Длинные провода + 400 кГц | Укоротить провода или снизить до 100 кГц |
| TCA9548A не найден | Pull-up резисторы отсутствуют | Установить 4.7 кОм на SDA + SCL |
| IMU выдаёт bias > 0.1 | Вибрация при калибровке | Робот ДОЛЖЕН стоять неподвижно 3 сек |

### 🎥 Камера не видит цвета
| Симптом | Причина | Решение |
|---------|---------|---------|
| Все пороги не работают | Автоэкспозиция/баланс белого | Убедиться `auto_gain=False, auto_whitebal=False` |
| Цвет «поплыл» при другом свете | Калибровка при другом освещении | Перекалибровать на месте |
| Путает красный и оранжевый | Пороги перекрываются | Сузить LAB-диапазоны в Threshold Editor |

### 🏎️ Робот едет криво
| Симптом | Причина | Решение |
|---------|---------|---------|
| Тянет вправо/влево | SERVO_CENTER неточен | Подобрать точное значение (88-92) |
| Дёрганый руль | Шумная PID производная | Проверить DERIVATIVE_ALPHA (уменьшить) |
| Не попадает в повороты | BLIND_TURN_ANGLE слишком мал | Увеличить до 90°+ |
| Проезжает стартовую линию | Cooldown слишком большой | Уменьшить LINE_DETECT_COOLDOWN_MS |

### 🔋 Питание
| Симптом | Причина | Решение |
|---------|---------|---------|
| ESP32 перезагружается | Просадка питания при пуске мотора | Добавить конденсатор 470 мкФ на 5V линию |
| Серво дёргается | Недостаточный ток LM2596 | LM2596 должен давать ≥ 2A |
| Батарея «проседает» | Разряд ниже 6.4V | Установить LiPo тестер для контроля |
